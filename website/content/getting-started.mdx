This guide installs Armada on your laptop and runs your first job. You'll use **Kind**, which runs a small Kubernetes cluster inside Docker; and the **Armada Operator**, which installs Armada into that cluster with one command.

By the end, you'll have Armada running, a job that has finished, and its output on your screen.

**Time needed:** about 30 minutes, most of it waiting for the install.

---

## What you'll be working with

- **Armada** — a batch job scheduler that runs on top of Kubernetes. You give it jobs, and it decides when and where each one runs, sharing the machines fairly between teams.
- **Job** — a container that runs to completion.
- **Queue** — where jobs wait. Each team usually has one.
- **`armadactl`** — the command-line tool you use to talk to Armada.
- **Lookout** — Armada's web interface for following jobs.

## Before you start

### Prerequisites

Make sure you have these running on your machine:

- **[Docker Desktop](https://docs.docker.com/get-docker/)** - or another Docker engine
- **[kubectl](https://kubernetes.io/docs/tasks/tools/)** - Command-line tool for Kubernetes
- **[Helm](https://helm.sh/docs/intro/install/)** - Package manager for Kubernetes
- **[Kind](https://kind.sigs.k8s.io/docs/user/quick-start/#installation)** - For creating a local Kubernetes cluster
- **[Make](https://www.gnu.org/software/make/)** - Build automation tool
- **[Go (v1.21 or later)](https://go.dev/doc/install)** - Required for the quickstart automation script

### Start Docker and give it enough memory

Armada runs inside Docker, so **Docker must be running the whole time you use Armada**. Armada's supporting services use about 6 GB of memory before you run anything.

In Docker Desktop, open **Settings → Resources** and set memory to **at least 8 GB**, then make sure Docker is running.

Check everything at once:

```bash
docker info > /dev/null && echo "Docker is running"
kubectl version --client
helm version
kind version
go version
```

<Callout type='info'>
  **Ready when:** you see `Docker is running` and a version for each tool, with
  Go at 1.21 or later.
</Callout>

### Make sure no old install is in the way

The install creates a cluster called `armada`. If you've tried Armada before, an old one may still exist:

```bash
kind get clusters
```

<Callout type='info'>
  **Ready when:** it prints `No kind clusters found.`
</Callout>

If it lists `armada`, delete the old install first. From the `armada-operator` folder you installed from before:

```bash
make kind-delete-cluster
```

Or, from anywhere:

```bash
kind delete cluster --name armada
```

## 1. Install Armada

<Steps>

<Step>

**Download the installer**

```bash
mkdir -p ~/armada-guide
cd ~/armada-guide
git clone https://github.com/armadaproject/armada-operator.git
cd armada-operator
```

</Step>

<Step>

**Run the install**

```bash
make kind-all
```

This one command:

- Creates a Kind cluster called `armada`
- Installs the services Armada depends on (PostgreSQL, Pulsar, and Redis)
- Installs Armada
- Installs `armadactl` into `~/bin`
- Writes `~/.armadactl.yaml`, which points `armadactl` at your new install (`localhost:30002`)

<Callout type='warn'>
  This takes **7 to 20 minutes**. It’s finished when a line ends in `condition
  met` and you get your prompt back. If you already have a `~/.armadactl.yaml`,
  back it up first — the install replaces it.
</Callout>

</Step>

</Steps>

---

## 2. Check Armada is running

```bash
kubectl get pods -n armada
```

**Success:** you see these pods, most of them `Running`:

```text title="Output"
armada-event-ingester-... 1/1 Running
armada-executor-... 1/1 Running
armada-lookout-... 1/1 Running
armada-lookout-ingester-... 1/1 Running
armada-lookout-migration-... 0/1 Completed
armada-scheduler-... 1/1 Running
armada-scheduler-ingester-... 1/1 Running
armada-scheduler-migration-... 0/1 Completed
armada-server-... 1/1 Running
```

Now check that `armadactl` can reach Armada:

```bash
armadactl get queues
```

**Success:** it prints no line containing `error`:

```text title="Output"
apiVersion: armadaproject.io/v1beta1
kind: Queue
[]
```

<Callout type='warn'>
  **Wait two minutes before Step 3.** After its pods start, Armada takes a
  little time to learn how much CPU and memory the cluster has. A job submitted
  before then fails with `exceeds the total limit`.
</Callout>

---

## 3. Run your first job

<Steps>

<Step>

**Create a queue**

```bash
armadactl create queue example
```

**Response:**
`Created queue example`

<Callout type='info'>
  Wait about 15 seconds before submitting. Armada checks for new queues every 10
  seconds — submitting to a brand-new queue straight away fails with `could not
  find queue`.
</Callout>

</Step>

<Step>

**Submit a job**

This command submits the example job and automatically captures its ID into a variable called `JOB_ID` so you can reference it in later commands.

```bash
JOB_ID=$(armadactl submit dev/quickstart/example-job.yaml | awk '{print $5}')
echo "Job ID: $JOB_ID"
```

**Response:**
`Job ID: <JOB_ID>`

<Callout type='info'>
  `JOB_ID` only lasts in this terminal window. If you open a new one, set it again: `JOB_ID=<JOB-ID>` (with your own ID). This job starts a small Linux container that prints `Hello Armada` and exits.
</Callout>

</Step>

<Step>

**Watch the job**

```bash
armadactl watch example job-set-1
```

**Response:**

```text title="Output"
Watching job set job-set-1
Month day time | Queued: 0, Leased: 0, ... | JobSubmittedEvent, job id: <job-id>
Month day time | Queued: 1, Leased: 0, ... | JobQueuedEvent, job id: <job-id>
Month day time | Queued: 0, Leased: 1, ... | JobLeasedEvent, job id: <job-id>
Month day time | Queued: 0, Leased: 0, Pending: 1, ... | JobPendingEvent, job id: <job-id> pod: 0
Month day time | Queued: 0, Leased: 0, ..., Succeeded: 1, ... | JobSucceededEvent, job id: <job-id> pod: 0
```

The job moves through: **Queued** → **Leased** → **Pending** → **Running** → **Succeeded**. A short job can finish before Armada reports it as Running, so you may not see that line.

<Callout type='info'>
  `watch` keeps running after the job finishes. Press **Ctrl-C** to stop it.
</Callout>

</Step>

</Steps>

---

## 4. See the job's output

```bash
kubectl logs -n default armada-$JOB_ID-0
```

**Response:**
`Hello Armada`

<Callout type='warn'>
  Run this immediately after the job succeeds. Finished pods are cleaned up within a minute or two and their output goes with them. If you see `pods "armada-[job-id]-0" not found`, the pod is already gone. Submit a new job and run `kubectl logs` straight after `watch` shows `JobSucceededEvent`.
</Callout>

---

## 5. Open Lookout

Open [http://localhost:30000](http://localhost:30000) in your browser.

**Success:** your job appears in the list, in queue `example`. Click it to see its details, the YAML you submitted, and its run history.

<Callout type='info'>
  On a laptop install, Lookout’s **Logs** tab shows `TypeError: Failed to
  fetch`. That’s expected — it needs a log service the laptop install doesn’t
  include. Use `kubectl logs` from Step 4 instead.
</Callout>

---

## Keeping your install working

- **Keep Docker running.** If Docker quits or restarts, the Kind cluster comes back but Armada doesn't recover. Reinstall it — see [Troubleshooting](#troubleshooting).
- **Your setup is reset by a reinstall.** Queues and job history are lost, so recreate any queues you need.

---

## Clean up

When you're done, delete the cluster and everything in it:

```bash
cd ~/armada-guide/armada-operator
make kind-delete-cluster
```

**Response:**
`Deleted nodes: [...]`

## Troubleshooting

<Accordions>

<Accordion title="Docker isn't running — failed to connect to the docker API">
  Start Docker Desktop and wait until it’s running. If Armada was already
  installed, reinstall it.
</Accordion>

<Accordion title='node(s) already exist for a cluster with the name "armada"'>
  A previous install is still there. Run `make kind-delete-cluster`, then `make
  kind-all` again.
</Accordion>

<Accordion title='command not found: armadactl'>
  `~/bin` isn’t on your PATH. Run `export PATH="$HOME/bin:$PATH"` and add that
  line to your shell profile.
</Accordion>

<Accordion title='The connection to the server localhost:8080 was refused from kubectl'>
  There’s no Kubernetes cluster. Run `kind get clusters`. If it doesn’t list
  `armada`, run `make kind-all`.
</Accordion>

<Accordion title='connection refused from armadactl'>
  Armada isn’t running. Check Docker is running, then run `kind get clusters`.
  If it doesn’t list `armada`, run `make kind-all`.
</Accordion>

<Accordion title='relation "queue" does not exist'>
  Armada is still starting. Wait 30 seconds and try again.
</Accordion>

<Accordion title='could not find queue "example"'>
  The queue was created moments ago. Wait 15 seconds and submit again.
</Accordion>

<Accordion title='watch says the job set does not exist'>
  The job hasn’t reached the event stream yet. Wait a few seconds and run
  `watch` again.
</Accordion>

<Accordion title='Job fails with exceeds the total limit'>
  Armada started moments ago and doesn’t yet know the cluster’s resources. Wait
  two minutes and submit again.
</Accordion>

<Accordion title='Job fails with insufficient resources available'>
  The job asks for more CPU or memory than the cluster has free. The quickest
  fix is to lower the job’s `requests` and `limits` (keep them equal) and submit
  again. Or give Docker more CPU or memory in Settings → Resources, then Apply &
  restart. Reinstall only if the cluster doesn’t come back after Docker
  restarts: reinstalling deletes your queues and job history.
</Accordion>

<Accordion title='kubectl logs says the pod was NotFound'>
  The finished pod has been cleaned up. Run a new job and read its output
  sooner.
</Accordion>

<Accordion title='Lookout Logs tab shows TypeError: Failed to fetch'>
  The laptop install has no log service. Use `kubectl logs -n default armada-<job-id>-0` instead.
</Accordion>

<Accordion title='zsh: no such file or directory: job-id'>
  A placeholder was pasted with its angle brackets. Replace `<job-id>`, including `<` and `>`, with your actual job ID.
</Accordion>

<Accordion title='kubectl logs says pods "armada--0" not found'>
  `JOB_ID` is empty — you’re in a new terminal or the submit failed. Set it again: `JOB_ID=<your-job-id>`.
</Accordion>

<Accordion title='Commands fail after Docker or your computer restarted'>
  Armada doesn’t recover from a Docker restart. From the `armada-operator`
  folder, run `make kind-delete-cluster`, then `make kind-all`, then recreate
  your queues.
</Accordion>

</Accordions>
